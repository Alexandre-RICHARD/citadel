## Tests end-to-end

Inventaire des scénarios pour Playwright, tiré des endpoints (`packages/specs`), des pages du front, du code des services et du §17 du [cahier de l'authentification](auth/cahier_des_charges.md) (ses points automatisables sont repris ici), puis vérifié en parcourant l'application. Ni la mise en place technique ni le nombre ne comptent : un scénario enchaîne autant de vérifications que nécessaire, tant que l'histoire reste logique. Périmètre : auth, Backlog, Game Death Counter, projets publics et contact. Hors périmètre : console d'administration, cas extrêmes (quota de mails épuisé, horloge du serveur avancée, base arrêtée, restauration, bannissement d'IP) : couverts par les tests d'intégration.

**Hypothèses**
- Un **récepteur de mails** (type mail catcher) remplace Brevo : chaque scénario y lit le lien et le code du dernier mail reçu par adresse. Prérequis : `MAIL_SENDER=memory` garde aujourd'hui les mails dans la mémoire du serveur sans les exposer, et le client Brevo vise une URL fixe ; il faudra un moyen de les lire (route réservée aux tests, ou URL de Brevo configurable vers un faux Brevo).
- Une base de test vierge avant chaque scénario, et des comptes créés par l'API pour ne pas rejouer l'inscription partout. « Compte A » et « compte B » : deux comptes sans lien, pour l'isolation.
- Simulés : IGDB (réponses figées : son quota et ses données ne sont pas le sujet), le flux d'Irigo (GTFS-RT binaire, relayé par `/irigo/…`), le serveur de jeu de Satisfactory (`http://localhost:8080`), `/banner.json` et les tuiles OpenStreetMap, par interception réseau de Playwright.
- Les codes TOTP sont calculés par le test avec l'heure réelle (pas précédent et suivant : `±1`) ; l'horloge du navigateur (`page.clock`) sert aux minuteries (mode édition, décomptes) ; les durées du serveur sont raccourcies dans `.env.test`.
- **[critique]** casse la sécurité ou les données d'un compte ; **[important]** parcours principal ; **[confort]** finition. **[manuel]** : non automatisable (rendu dans Gmail ou Outlook, QR code lu par une application, Edge, DNS, mail-tester).
- ✅ : scénario écrit dans `e2e/src/tests` (le fichier est préfixé par son code : `a1.…`, `h2.…`). Les points constatés en les écrivant sont dans [problemes.md](problemes.md).
- **Écriture et validation** : les tests seront écrits avec un mode lent (`slowMo` de Playwright, éventuellement navigateur visible ou pause entre les étapes), pour que tu les regardes tourner et valides que chaque scénario est complet et correct avant de les laisser en exécution rapide.

### 1 Auth : inscription

- ✅ **A1 Inscription nominale** [critique] : depuis `/backlog` (déconnecté, renvoyé à la connexion, puis « Créer un compte »), formulaire (email, pseudo, mot de passe deux fois, « Se souvenir de moi ») → « Créer mon compte » → écran « Confirme ton adresse email » (adresse affichée, « Il te reste 29 min 59 s… » qui défile, « Renvoyer l'email (59 s) ») → lien du mail ouvert dans le même navigateur : « Un clic pour confirmer », puis « Confirmer » : le compte est créé, connecté, et l'étape « Protège ton compte » est proposée ; « Annuler » (qui devient « Plus tard » une fois « Continuer » cliqué) ramène à `/backlog`. Aucune ligne `auth_user` avant la confirmation. Le texte « Reste connecté 7 jours sans visite, 30 jours au plus » est sous la case.
- ✅ **A2 Inscription par le code** [critique] : même parcours, mais le code du mail est tapé dans l'onglet resté ouvert (« Valider le code »), sans le lien.
- **A3 Contrôles du formulaire** [important] : pseudo (espace, accent, `.`, 65 caractères refusés avant l'envoi ; `_`, `-` et 64 caractères acceptés ; « Vérifier la disponibilité » inactif tant qu'il est mal formé) ; email sans espace (impossible à taper ou coller) ; mot de passe de 11 caractères refusé, 12 et 128 acceptés, 129 refusé ; « Les deux mots de passe sont différents. » ; l'œil affiche et masque les deux champs ; conditions au vert en direct ; barre de force « Très faible » pour `azertyuiop12`, `aaaaaaaaaaaa`, `123456789012`, avec son « ? » ; champs fautifs coloriés à l'envoi ; astérisque rouge sur chaque champ obligatoire ; messages des 30 minutes et du gestionnaire de mots de passe ; email avec lettre pleine chasse, ligature ou caractère invisible refusé.
- **A4 Pseudos et emails distincts** [critique] : `Alex` et `alex` coexistent ; `Alex@…` refusé après `alex@…` ; `josé@…` et `jose@…` coexistent ; « Vérifier la disponibilité » juste pour un pseudo pris, libre ou ne différant que par la casse (« Ce pseudo est libre. » / « Ce pseudo est déjà pris. »). À la connexion, la casse compte pour le pseudo (`alexqa` n'ouvre pas `AlexQA`), pas pour l'email.
- **A5 Adresse déjà inscrite** [critique] : même écran que l'inscription nominale (aucune fuite), mais le mail dit « Tu as déjà un compte… » avec la durée de dernière connexion et un lien vers la connexion, sans code.
- **A6 Parcours concurrents** [important] : deux inscriptions avec la même adresse, seule la dernière se confirme ; pseudo pris entre l'envoi et la confirmation : la page redemande un pseudo (« Nouveau pseudo »), le code reste valable ; commencer un autre parcours dans le même navigateur abandonne le premier ; double clic sur « Créer mon compte » : un seul compte.
- **A7 Champ piège** [important] : champ « Site web » rempli par script → réponse normale, aucun mail, aucun compte, l'écran du code tient au rechargement ; une vraie inscription en attente à la même adresse reste valable.
- **A8 Inscriptions fermées** [confort, interrupteur `AUTH_REGISTRATION_ENABLED` à `false`] : formulaire désactivé et bandeau « …elles rouvrent demain ».

### 2 Auth : lien, code et reprise (communs à tous les parcours)

- ✅ **B1 Reprise après rechargement** [important] : à chaque étape (formulaire d'inscription, de connexion, de mot de passe oublié, écran du code, second facteur, nouveau mot de passe), un rechargement ramène au même endroit ; les champs sont gardés, jamais les mots de passe.
- ✅ **B2 Lien dans un autre onglet** [important] : le lien ouvert dans un second onglet du même navigateur valide ; au retour sur l'onglet d'origine, la page passe seule à la suite.
- **B3 Lien dans un autre navigateur** [critique] : le lien est refusé avec le message d'utiliser le code (« Ce lien a été ouvert dans un autre navigateur… », sans bouton « Confirmer ») ; le code tapé dans le navigateur d'origine marche.
- **B4 Page d'arrivée du lien** [critique] : ouvrir `/auth/verify` sans cliquer ne valide rien ; le jeton est dans le fragment, retiré de la barre d'adresse et de l'historique dès la lecture, et ne part dans aucune requête ; sans fragment, ou abîmé : « Lien incomplet », qui renvoie au code de l'email.
- **B5 Codes** [critique] : code collé avec des espaces accepté ; 5 chiffres, bouton désactivé ; code déjà utilisé refusé ; 5 mauvais codes bloquent (« Tous les essais de ce code sont faits : demande un nouvel email. », champ grisé), le renvoi remet les essais à zéro ; ancien code refusé après un renvoi ; code tapé pendant qu'un autre onglet renvoie : « code faux », le parcours continue.
- **B6 Renvoi et délais** [important] : bouton grisé 60 s avec compte à rebours, puis « Un nouvel email est parti : seul son code est valable maintenant. » ; temps restant du parcours qui défile ; renvoi refusé par une limite de mails : l'attente imposée est affichée.
- **B7 Parcours expiré** [important, durée raccourcie dans `.env.test`] : « Le délai est dépassé : ce code et ce lien ne marchent plus. », lien et code refusés, « Recommencer » ramène au formulaire.
- **B8 Abandon** [confort] : « Recommencer » supprime le parcours, un rechargement revient au formulaire.
- **B9 Lien devenu invalide** [important] : lien déjà utilisé, remplacé par un renvoi ou expiré : « Ce lien n'est plus valable… » avec « Se connecter » et « Créer un compte », sans bouton « Confirmer » ; pseudo pris entre l'envoi et le clic : champ « Nouveau pseudo », le lien reste valable.

### 3 Auth : connexion

- ✅ **C1 Connexion nominale** [critique] : par email puis par pseudo ; session ouverte, retour à la page demandée, ou au profil sans page demandée ; avec « Se souvenir de moi » le cookie a un `Max-Age` de 7 jours, sans la case il n'en a pas ; le formulaire garde l'identifiant (pas le mot de passe) au rechargement.
- ✅ **C2 Mauvais identifiants** [critique] : identifiant inconnu et mauvais mot de passe donnent le même message (« Impossible de te connecter : identifiant ou mot de passe incorrect. ») et vident le mot de passe ; temps de réponse comparables.
- ✅ **C3 Délai entre essais** [important] : deux essais à moins de 2 s → bouton désactivé avec compte à rebours ; le délai vise le compte : un mauvais mot de passe par pseudo, puis aussitôt par l'adresse du même compte, attend ; par l'adresse d'un autre compte, non.
- **C4 Connexion par lien** [critique] : « Recevoir un lien de connexion par email » → « Recevoir le lien » par email, puis par pseudo ; écran « Vérifie tes emails » identique pour un identifiant inconnu ; lien lié au navigateur (B3) ; retour à « Me connecter avec mon mot de passe ».
- **C5 Méthodes choisies** [important] : « par email » seul : le mot de passe échoue comme un mauvais ; « par pseudo » seul : le lien ne part pas, écran identique ; la méthode fermée dans un autre onglet pendant un parcours invalide lien et code.
- ✅ **C6 Déjà connecté** [important] : `/auth/login` renvoie vers le profil ; une nouvelle connexion dans le même navigateur retire l'ancienne session de la liste.
- **C7 Cookies** [critique] : cookie de session `HttpOnly`, `SameSite=Lax`, `Path=/`, sans `Domain` ; nommé `citadel_session` sans `Secure` quand `AUTH_COOKIE_SECURE` est `false`, `__Host-citadel_session` avec `Secure` sinon (le cas de `.env.test`, qui ne le pose pas : Chromium l'accepte sur localhost) ; renvoyé au plus toutes les 5 minutes avec « se souvenir de moi » (délai raccourci dans `.env.test`) ; cookie de parcours `citadel_flow` seulement pendant un parcours ; cookie de session modifié à la main → `401` et retour à `/auth/login`.
- **C8 Redirection sécurisée** [critique] : `?redirect=` vers un autre domaine, `//ailleurs` ou une adresse avec `\` ne fait jamais quitter le site ; vers une page du site, respecté ; la page demandée traverse l'inscription ou le mot de passe oublié dans le même onglet.

### 4 Auth : mot de passe oublié

- **D1 Parcours complet** [critique] : « Mot de passe oublié ? » depuis la connexion → email ou pseudo → réponse identique pour un compte existant ou non, adresse jamais affichée → lien ou code → nouveau mot de passe deux fois (« Enregistrer et me connecter ») → connecté ; mail de notification reçu ; les sessions des autres navigateurs sont fermées.
- **D2 Règles** [important] : le mot de passe actuel est refusé (`PASSWORD_UNCHANGED`) ; barre de force et conditions comme à l'inscription ; « Les deux mots de passe sont différents. ».
- **D3 Avec TOTP** [critique] : le TOTP (ou un code de secours) est demandé après le lien ; le code par email n'est jamais proposé.

### 5 Auth : double authentification

- ✅ **E1 Activer un TOTP** [critique] : depuis l'étape « Protège ton compte » puis depuis le profil ; nom du facteur (« Mon application » par défaut), « Continuer », QR code et clé manuelle affichés, un code faux refusé (« ce code n'est pas valable »), le premier code valide active ; « Plus tard » avant l'activation ne crée rien dans la liste ; les 10 codes de secours s'affichent une fois (deux groupes de 5), se téléchargent (`citadel-codes-de-secours-AAAA-MM-JJ.txt`), « Terminé » inactif tant que le fichier n'est pas téléchargé ou la case cochée, et ils ne reviennent pas au rechargement ; le secret n'est dans aucune réponse suivante.
- ✅ **E2 Codes TOTP** [critique] : pas précédent et suivant acceptés, deux pas d'écart refusés ; le même code deux fois refusé (codes calculés par le test).
- ✅ **E3 Connexion avec 2FA** [critique] : mot de passe → « Double authentification » avec le choix entre Application, Code par email et Code de secours selon le compte (choix absent s'il n'y a qu'une méthode), « Il te reste 9 min 59 s pour te connecter » ; aucune session avant la fin ; TOTP valide → connecté.
- **E4 Facteur mail** [important] : activation par le code (profil) puis par le lien (`/auth/verify` montre alors les codes de secours) ; « Recevoir un code par email » puis « Renvoyer l'email » avec son délai ; le lien de cet email, ouvert dans le même navigateur, connecte aussi ; un code tapé sans avoir demandé l'email est refusé sans compter.
- **E5 Connexion par lien avec 2FA** [critique] : avec un TOTP, il est demandé et le code par email n'est jamais proposé ; avec le seul facteur mail, rien de plus.
- ✅ **E6 Codes de secours** [critique] : chacun marche une fois, en minuscules, sans tiret ou avec des espaces ; nombre restant juste (« 10 codes de secours utilisables », « Aucun code de secours utilisable : refais-en. ») ; régénération (mot de passe demandé, « Les anciens codes… ne marcheront plus ») : les anciens refusés.
- ✅ **E7 Gestion des facteurs** [important] : deux TOTP nommés plus le facteur mail, liste avec nom, type, « Ajouté le… · jamais utilisé / utilisé le… » ; « Activer le code par email » absent une fois le facteur actif ; suppression avec le mot de passe ; supprimer le dernier désactive la 2FA et efface les codes de secours (« Aucune double authentification… ») ; notifications reçues.
- **E8 Échecs de second facteur** [critique] : comptés comme des échecs de connexion (15 mauvais codes bannissent le couple compte + IP même entrecoupés du bon mot de passe) ; distincts d'un mauvais mot de passe dans `auth_event`.
- **E9 Concurrence** [important] : même TOTP confirmé depuis deux onglets : un seul lot de codes de secours, message clair dans l'autre ; facteur mail activé depuis deux onglets : un seul dans la liste ; facteur retiré dans un autre navigateur pendant l'étape de connexion : l'étape le prend en compte, ou propose de recommencer.

### 6 Auth : limites et abus

- **F1 Verrouillage du couple compte + IP** [critique] : 15 échecs → message avec `Retry-After` ; le même compte s'ouvre depuis une autre IP ; le bon mot de passe passe de nouveau après l'attente (IP simulée et durée raccourcie).
- **F2 Un inconnu ne bloque pas ton compte** [critique] : échecs répétés depuis une autre IP, la connexion légitime reste possible sans compte à rebours.
- **F3 Limites de mails** [important] : 5 par heure et par forme d'identifiant, 20 par heure et 40 par jour par IP ; la 6e inscription à une même adresse n'interdit pas l'IP.
- **F4 CSRF** [critique] : requête non sûre avec un `Origin` étranger → `403` traduit ; les `GET` d'un autre site passent.
- **F5 Pas de fuite dans l'interface** [critique] : aucun mot de passe, code, jeton ni lien dans l'URL finale, les requêtes, le `sessionStorage` ou la console du navigateur.

### 7 Auth : profil, sessions, données

La page `/auth/profile` enchaîne six sections : Identité, Mot de passe, Méthodes de connexion, Double authentification (E1 à E9), Sessions actives, Mes données. Un parcours du profil en cours (nouvelle adresse, code par email) prend la place de la page.

- **G1 Identité** [important] : pseudo et email en lecture seule ; « Pseudo affiché » : espaces de début, de fin et en double nettoyés (`  Alex   le   QA  ` → `Alex le QA`), accents permis, vide = le pseudo, 65 caractères et caractère invisible refusés ; « Enregistrer » inactif sans changement, puis « Pseudo affiché enregistré. » ; le header de la homepage le montre ; le pseudo définitif ne change pas.
- ✅ **G2 Changement de mot de passe** [critique] : ancien redemandé (faux : « le mot de passe est incorrect », champ vidé), même mot de passe refusé, « Changer mon mot de passe » inactif tant que les trois champs ne sont pas cohérents, puis « Mot de passe changé. Tes autres sessions ont été fermées. » : les autres sessions fermées et celle-ci gardée, notification reçue.
- ✅ **G3 Changement d'email** [critique] : « Changer mon adresse email » (« Annuler » referme), mot de passe demandé, la page passe à « Confirme ta nouvelle adresse email » ; lien et code à la nouvelle adresse, notification à l'ancienne, puis retour au profil avec la nouvelle adresse ; même adresse (même en majuscules) refusée tout de suite ; adresse déjà prise : même écran, et seul son propriétaire reçoit un mail « un autre compte a voulu… » sans lien ni code ; prise entre-temps : `EMAIL_TAKEN` ; lien dans un autre navigateur refusé.
- **G4 Méthodes de connexion** [important] : « Les deux » par défaut ; « Par email » et « Par mon pseudo (et mot de passe) » s'enregistrent tout de suite et tiennent au rechargement ; la connexion les respecte (C5) ; une erreur d'enregistrement s'affiche avec « Réessayer ».
- ✅ **G5 Sessions** [important] : liste (« Edge sur Windows », « Cette session », dernière activité, « Ouverte le… · fin prévue le… », « Réseau » + IP tronquée) ; user agent de plus de 255 caractères tronqué ; « Déconnecter » une autre session (l'autre navigateur retombe sur la connexion à son prochain appel) ; « Tout déconnecter sauf ici » inactif avec une seule session ; session déjà fermée ailleurs : « cette session n'existe plus, elle a peut-être déjà été fermée » ; « Me déconnecter » et « Tout déconnecter » renvoient à la connexion et effacent le cookie ; boutons inactifs pendant une action.
- ✅ **G6 Déconnexion et deux navigateurs** [critique] : un clic sur « Se déconnecter » (header de la homepage), sans confirmation ; deuxième requête sans erreur ; les autres onglets renvoient vers la connexion à leur prochain appel et n'affichent plus rien du compte ; avertissement « Se déconnecter maintenant ? » seulement avec une mutation en cours (« Annuler » garde la session) ; connecté sur deux navigateurs, se déconnecter de l'un laisse l'autre connecté.
- **G7 Actions sensibles** [critique] : le mot de passe est redemandé pour changer d'adresse ou de mot de passe, retirer un facteur, refaire les codes de secours, vider un projet et supprimer le compte ; un mauvais mot de passe ne change rien et impose le délai de la connexion (bouton « Patiente… ») ; suppression du compte : champ « Code de ton application, ou code de secours » en plus quand un TOTP existe, jamais pour le seul facteur mail ; code de secours faux répété → « trop d'essais », compte à rebours qui ne s'efface pas en redonnant le bon mot de passe.
- **G8 Export** [important] : « Télécharger mes données » donne `citadel-mes-donnees-AAAA-MM-JJ.zip` avec la session (`401` sans) ; 13 CSV (`auth_user`, `auth_session`, `auth_factor`, `auth_recovery_code`, `auth_event`, `auth_flow`, `gdc_game`, `gdc_boss`, `gdc_death`, `backlog_user_game`, `backlog_user_version`, `backlog_done_dlc`, `backlog_series`) avec les lignes du compte et aucun hash, empreinte ni secret ; accents conservés ; `backlog_series.csv` nomme chaque série du backlog, séries IGDB comprises.
- **G9 Suppression des données d'un projet** [critique] : « Choisir les projets à vider » → cases Game Death Counter et Backlog (astérisque rouge), « Supprimer définitivement ces données » inactif sans case ; vider l'un sans l'autre, ou les deux ; mauvais mot de passe : rien n'est vidé ; « Les données de … sont supprimées. » ; le projet vidé s'ouvre vide sans rechargement, le compte et l'autre projet restent.
- ✅ **G10 Suppression du compte** [critique] : écran « La suppression est immédiate et définitive. Aucun délai de récupération. », mot de passe (et TOTP) ; mail de confirmation ; retour à la homepage ; reconnexion impossible ; aucune donnée restante ; l'adresse et le pseudo sont réutilisables.

### 8 Accès, header et navigation

- ✅ **H1 Projets privés** [critique] : déconnecté, GDC, Backlog et `/auth/profile` renvoient à `/auth/login?redirect=…` puis ramènent au même endroit (aussi par « Y accéder » de la vitrine) ; Homepage, Satisfactory et Angers Irigo restent publics.
- ✅ **H2 Header de la homepage** [important] : « Se connecter » déconnecté (rien tant que `GET /auth/me` n'a pas répondu) ; icône, pseudo affiché et « Se déconnecter » connecté ; profil et déconnexion en icônes sur mobile, header sur une ligne.
- **H3 Session expirée en cours d'action** [critique] : une modification du Backlog ou de GDC avec une session supprimée mène à la connexion, sans toast « Impossible de… » par-dessus ; un autre compte connecté ensuite dans le même onglet ne voit rien du premier.
- **H4 Icônes de profil et retour** [confort] : « Mon profil » dans le Backlog et GDC ; « Retour à la Citadel » depuis chaque projet rouvre sa présentation (`/homepage/<projet>`) ; `auth` absent de la roue et du pied de page.
- **H5 Pages de l'auth** [confort] : clair et sombre, mobile, clavier seul, zoom à 200 % ; une adresse inconnue sous `/auth` mène à la connexion ; aucune violation de CSP dans la console sur chaque page ; **[manuel]** une seule icône d'œil sous Edge.

### 9 Isolation entre comptes

- ✅ **I1 Endpoints protégés** [critique] : sans session, tous les endpoints GDC, Backlog (IGDB compris) et `/auth/me`, `/sessions`, `/factors`, `/me/export` répondent `401`.
- ✅ **I2 GDC** [critique] : le jeu, le boss ou la mort d'un autre compte (identifiant tapé dans l'URL ou l'API) → `404` ; la liste de A ne montre rien de B.
- **I3 Backlog** [critique] : jeux suivis, versions jouées, séries manuelles d'un autre compte → `404` ; une série manuelle de A est invisible pour B ; les séries IGDB sont communes.
- **I4 Base commune** [important] : un jeu enregistré par A apparaît dans « Ajouter un jeu depuis la Citadel » de B sans la personnalisation de A ; ajouté aux deux backlogs, chacun garde ses versions jouées.

### 10 Game Death Counter

- **J1 Jeux** [important] : liste vide (« Aucun jeu enregistré ») ; « Nouveau jeu » (Entrée ou « Créer le jeu », « Annuler » ; inactif pour un nom vide ou d'espaces ; message au-delà de 255 caractères) ; jeux triés par nom, « Débuté le… », total général dans l'en-tête ; renommer (« Enregistrer » / « Annuler ») ; « Marquer comme terminé » (pastille « terminé », « · terminé le… ») et « Marquer non terminé » ; suppression avec confirmation (« Ses boss et ses N morts seront supprimés définitivement. », Annuler ou Échap) et cascade ; chargement affiché.
- **J2 Boss** [important] : jeu déplié (« Aucun boss enregistré pour ce jeu. ») ; « Ajouter un boss » (nom obligatoire, 255 caractères, Entrée, « Annuler ») ; boss dans l'ordre de création ; renommer ; « Marquer comme vaincu » (pastille « vaincu », date) et annuler ; suppression avec confirmation (« Cette action est définitive. », « Sa mort… », « Ses N morts… ») ; le total du jeu suit.
- **J3 Morts** [critique] : « Ajouter une mort (+1) » ajoute une mort immédiatement (optimiste, à l'instant) et les totaux du boss, du jeu et de l'en-tête suivent ; boss déplié sans mort (« Aucune tentative enregistrée… ») ; morts triées par date ; modifier la date (pas dans le futur) et le commentaire (« sans commentaire » sinon, 1000 caractères), « Annuler » ; supprimer sans confirmation ; « Débuté le… » du boss = sa première mort ; rechargement : tout persiste.
- **J4 Erreurs et latence** [important, API ralentie ou coupée] : une mutation en échec annule l'affichage optimiste et affiche un toast « Impossible de… : raison. » avec « Réessayer » pour une panne passagère ; boss, jeu ou mort supprimés dans un autre onglet : « ce boss n'existe plus » et la ligne disparaît ; jamais de doublon après un double clic.
- **J5 Persistance au retour** [confort] : navigation vers un autre projet puis retour : même état, thème conservé.

### 11 Backlog

Sauf mention contraire, les scénarios d'édition passent par le mode édition (K7) et les données sont créées par l'API.

- **K1 Backlog vide, chargement et lecture en échec** [important] : « Le backlog est vide » avec « Rechercher un jeu » (met le curseur dans la recherche) ; « 0 jeu · 0 version jouée » ; squelette « Chargement du backlog » ; lecture en échec : « Impossible de charger le backlog : … » avec « Réessayer » pour une panne passagère ; « Ajouter un jeu depuis la Citadel » avec son compteur, désactivé (« Tous les jeux de la base sont dans le backlog ») quand tout est déjà dans le backlog.
- **K2 Recherche IGDB** [critique] : « / » met le curseur dans la recherche (pas depuis un champ, pas avec une modale ouverte) ; saisie (« Recherche sur IGDB… »), résultats (miniature, nom français et original, année, 3 plateformes puis « +n », « via … » quand une autre fiche est trouvée), badges « Déjà en base » et « Dans le backlog », « Aucun résultat pour « … » » ; ↓ ↑ Entrée choisissent, Échap ferme la liste, la croix efface, un clic ailleurs ferme ; IGDB indisponible : « Impossible de rechercher sur IGDB : IGDB ne répond pas. ».
- **K3 Enregistrer un jeu en base** [critique] : un résultat pas encore en base ouvre « Ajouter un jeu » (« Chargement des données IGDB… ») ; fiche en lecture seule (sortie, « Ouvrir sur IGDB », série proposée, développeur, éditeur) ; versions à enregistrer (l'originale et celles déjà en base cochées et verrouillées, compteur « x / y ») et DLC (« Aucun DLC » sinon) ; « Données IGDB hors modèle (n) » dépliable ; « Valider » avec « Ajouter à mon backlog » cochée enchaîne sur K4, décochée ferme la modale et le jeu rejoint « Ma base » (compteur +1) ; « Annuler » n'enregistre rien ; jeu déjà ajouté par un autre onglet : « Ce jeu est déjà en base : seules les fiches manquantes s'ajouteront » ; fiche introuvable ou IGDB en échec : message dans la modale.
- **K4 Ajouter au backlog** [critique] : depuis K3, depuis un résultat déjà en base (version trouvée présélectionnée) ou depuis « Ajouter un jeu depuis la Citadel » (K6). Personnalisation : miniature à choisir (« Chargement des images IGDB… », « Aucune image sur IGDB », échec : « Impossible de charger les images… » et l'image courante reste) ; type de fin (Histoire par défaut, explication sous le choix) ; série (celle d'IGDB, « Aucune », une autre, « Nouvelle série… » avec son nom obligatoire, « Série IGDB » pour revenir) et numéro (K15). Version jouée : la version puis la plateforme (celles de la version, puis les émulateurs « émulateur » ; un couple déjà joué est grisé « déjà dans le backlog » ; « D'abord la version »). Mes données : statut, date de fin, fois fini sûr et probable, temps relevé et estimé, note sur 20, « À jouer bientôt », « Possédé », commentaire, DLC faits. « Valider » inactif sans version ni plateforme, erreur de saisie dans un encadré rouge ; changer le type de fin ramène le statut à un statut compatible ; un statut de rang 5 ou plus sans date de fin ouvre « Date de fin » (K9) ; « Annuler » laisse le jeu en base, hors du backlog ; la ligne apparaît en tête, grisée, puis normale ; les compteurs et « Ma base » suivent.
- **K5 DLC « comme jeu »** [important] : cocher « Comme jeu » sur deux DLC dans K3 ou K13 : après « Valider », l'ajout du premier DLC s'ouvre, puis celui du second, même par « Annuler » ; le DLC reste aussi DLC du jeu d'origine ; case grisée (« Déjà en base comme jeu ») pour un DLC déjà jeu.
- **K6 Ajout depuis « Ajouter un jeu depuis la Citadel »** [important] : filtrer par nom ou titre de version (« Aucun résultat »), ↓ ↑ Entrée, 50 jeux puis la page suivante au défilement (« n jeux de plus… »), choisir un jeu, l'ajouter sans IGDB ; « Tous les jeux de la base sont dans le backlog » quand il n'en reste aucun ; échec de lecture dans la modale ; supprimer un jeu de la base (confirmation, la ligne disparaît et le compteur baisse), refusé avec le motif si un compte l'a dans son backlog (la ligne revient).
- **K7 Mode édition** [critique] : lecture seule par défaut (cellules en valeurs ou en icônes, menu des actions avec les entrées grisées et l'infobulle « Disponible en mode édition », « Ouvrir sur IGDB » reste actif et s'ouvre dans un nouvel onglet) ; l'interrupteur « Édition » (tag « Mode édition · retour en lecture seule après 1 min sans activité ») active l'édition ; retour automatique en lecture seule après 1 minute sans activité (horloge pilotée), sauf cellule en cours d'édition ou modale ouverte.
- **K8 Édition des cellules** [critique] : sur une ligne à une seule version jouée, ou sur une sous-ligne : statut, cases « À jouer bientôt » et « Possédé », date de fin (`17/09/2013`, `17092013`, `2013-09-17`, calendrier au bouton ou Alt+↓ ; date impossible comme `31/02` ou incomplète : le champ revient à la valeur enregistrée), fois fini (sûr + probable), temps relevé et estimé (heures et minutes), note (entier de 0 à 20), commentaire (vide : effacé) ; enregistré à la sortie du champ ou avec Entrée, rien si la valeur ne change pas, une valeur refusée remet l'ancienne ; « Temps total » = relevé + estimé ; la ligne d'un jeu à plusieurs versions jouées reste en lecture seule (agrégats) ; un échec annule l'affichage et affiche le toast.
- **K9 Règles de statut, de type de fin et de fois fini** [critique] : types de fin Histoire et Runs : « Vu sans jouer » et « Fini » proposés, pas « Estimé fini » ; Bac à sable et Multijoueur : « Estimé fini » proposé, ni « Vu sans jouer » ni « Fini » ; les autres statuts pour tous, le statut actuel toujours listé. Au passage au rang 5 ou plus (Fini, Estimé fini, Complété, Platiné, Complété et Platiné) : « fois fini (sûr) » passe de 0 à 1 (sauf si la même saisie fixe ce compteur) ; sans date de fin, « Date de fin » (« Quand l'as-tu fini pour la première fois ? », pré-remplie à aujourd'hui) : « Valider » enregistre la date, « Plus tard » n'en met aucune (aussi à l'ajout au backlog) ; repasser sous le rang 5 n'efface ni la date ni le compteur. « Personnaliser » avec un autre type de fin convertit Fini ↔ Estimé fini et Vu sans jouer → Pas commencé (avertissement dans la modale), les statuts compatibles ne bougent pas. Ligne d'un jeu à plusieurs versions : « Pas commencé » ignoré tant qu'une autre version a un statut ; au moins un rang 5 ou plus : le plus haut ; toutes « Abandonné » : Abandonné ; sinon le plus haut ; « Abandonné » mêlé à un statut en cours : cellule vide. Autres agrégats : « À jouer bientôt » et « Possédé » si l'une des versions l'est, date de fin la plus ancienne, fois fini en somme (`2 (+1 ?)`), temps en somme, note la plus haute, commentaire seulement s'il n'y en a qu'un.
- **K10 Plusieurs versions jouées** [critique] : « Ajouter une version jouée » (versions et plateformes de la base, couple déjà joué grisé) à un jeu déjà présent ; la ligne devient dépliable (chevron, nombre de versions, → déplie et ← replie au clavier), ses sous-lignes (« Version originale » ou titre de la version, plateforme, données modifiables, menu propre « Ouvrir la version sur IGDB » / « Retirer la version jouée ») ; retirer une version avec confirmation (« La version jouée sur PS2 et ses données (statut, temps, note…) seront supprimées. ») : à une seule restante, la ligne redevient simple ; unicité version + plateforme ; l'état déplié est gardé le temps de la page.
- **K11 Retrait** [critique] : « Retirer le jeu du backlog » avec confirmation (« … quitte le backlog avec sa version jouée et sa personnalisation. Le jeu reste en base. », « Annuler » ou Échap) ; jeu absent du tableau et de ses compteurs mais présent dans « Ma base » ; ligne déjà retirée par un autre onglet : « Impossible de retirer le jeu du backlog : ce jeu n'est plus dans le backlog. » et la ligne disparaît ; retirer la dernière version jouée retire le jeu (par l'API : l'écran ne le propose pas, K10).
- **K12 DLC** [important] : colonne « DLC » : « faits / total » avec sa jauge, verte quand tout est fait ; le panneau « DLC faits » (lecture seule : « Lecture seule » et coches ; édition : cases enregistrées tout de suite, grisées le temps de l'envoi) ; jeu sans DLC : cellule vide, et en édition un bouton « + » (« DLC : en rechercher ») ; « Rechercher d'autres DLC » (DLC d'IGDB, ceux en base cochés et verrouillés « Déjà en base », « Aucun DLC sur IGDB », « Valider » inactif sans nouvelle case) : les DLC ajoutés rejoignent toutes les versions jouées, non faits ; sur un jeu à plusieurs versions, « faits / total » compte un DLC fait sur au moins une version.
- **K13 Modifier le jeu** [important] : modale en lecture seule des données de la base, complétée à l'ouverture des versions et DLC d'IGDB qui manquent, à cocher pour les ajouter ; « Valider » inactif sans case ; les versions ajoutées sont ensuite proposées par « Ajouter une version jouée » ; DLC « comme jeu » (K5) ; chargement et échec d'IGDB dans la modale.
- **K14 Personnaliser** [important] : la modale montre les valeurs actuelles (image, type de fin, série, numéro) ; « Valider » inactif sans changement ; changer chaque valeur la met à jour dans le tableau ; avertissement de conversion des statuts (K9) ; jeu retiré entre-temps : « Ce jeu n'est plus dans le backlog. ».
- **K15 Séries** [important] : « Nouvelle série… » par son nom (un nom déjà pris, sans tenir compte des accents ni des majuscules, désigne la série existante) ; numéro `3`, `3.1`, `3,1` (3 décimales au plus, sous 1 refusé : le champ revient) ; sans numéro, le jeu passe après les autres (numéro grisé en indication) ; numéro pris : « N° 2 déjà pris par … : il sera décalé d'un cran, avec les suivants si besoin » et le décalage se retrouve dans le tableau ; changer de série vide le numéro, revenir à la série d'origine le rend ; le crayon « Série modifiée ; IGDB propose : … » quand la série n'est pas celle d'IGDB ; une série manuelle sans jeu disparaît des choix ; un clic sur un nom de série filtre le tableau sur cette série (K17). « Réorganiser la série » : entrée grisée sans série (« Ce jeu n'a pas de série ») ou pour une série « en cours de création » ; modale (jeu d'origine mis en valeur) : glisser une poignée entre deux lignes ou un peu à droite pour un sous-jeu, ou taper le numéro ; « Avant : n » sur les numéros changés ; « Sorti avant …, placé plus haut » signalé ; « Valider » inactif sans changement ; liste devenue caduque entre-temps : « la série a changé entre-temps ».
- **K16 Tri** [important] : un clic sur un en-tête trie croissant, puis décroissant, puis retire le tri ; plusieurs colonnes se cumulent, avec leur numéro de priorité, une flèche et `aria-sort` ; Miniature et Actions ne se trient pas ; les textes se comparent sans accents ni majuscules, les nombres dans l'ordre (« FF2 » avant « FF10 ») ; statuts et types de fin dans l'ordre de l'échelle ; les cases vides en dernier quel que soit le sens ; sans tri, l'ordre d'ajout ; le tri vit dans l'URL (`?sort=name:asc,status:desc` : rechargement, retour arrière, lien copié) ; un tri illisible dans l'URL est ignoré.
- **K17 Filtres** [important] : un filtre par colonne, cumulés (ET), dans la ligne sous les en-têtes : texte « Contient… » (sans accents ni majuscules ; la colonne Nom cherche aussi le nom original et le titre de la version ; attente de la fin de la frappe), valeur exacte « = » après un clic sur une série, liste (Type de fin, Statut, Plateforme parmi les plateformes jouées, « Tous »), Oui / Non (« À jouer bientôt », « Possédé »), plage de nombres (bornes incluses, temps saisis en heures, résumé « ≥ 1 », Entrée ou Échap referment) et plage de dates (« Depuis », « Jusqu'à ») ; un jeu reste affiché si sa ligne, ou une de ses versions jouées, correspond à tous les filtres (Plateforme = PCSX2 garde le jeu qui a une version sur PCSX2) ; « n jeux sur N » et « k filtres actifs » ; « Aucun jeu ne correspond aux filtres. » avec « Effacer les filtres » ; « Effacer tous les filtres » vide aussi les champs ; la vue vit dans l'URL (`?name=final&finishCount=1..`) ; un filtre illisible est ignoré.
- **K18 Colonnes et en-têtes** [confort] : « Colonnes » (« n sur 21 affichées ») : interrupteurs, « Monter » et « Descendre » (le focus passe à l'autre bouton en bout de liste), « Actions » toujours visible, effet immédiat ; masquer une colonne la retire du tri et des filtres ; visibilité et ordre conservés au rechargement ; bulles « Signification » des colonnes Type de fin (4 types) et Statut (10 statuts, avec leur rang) ; en-têtes compacts (N°, Sortie, icônes) avec le libellé complet en infobulle.
- **K19 Pages et chargement** [important] : plus de 25 jeux : la page suivante se charge à l'approche du bas (« Chargement… ») jusqu'au dernier ; changer le tri ou un filtre garde les lignes précédentes grisées avec « Mise à jour… » jusqu'à la nouvelle lecture ; le compteur dit le total, pas la page.
- **K20 Rendu des lignes et totaux** [confort] : nom français avec le nom original dessous, titre de la version sur une ligne à version unique ; « Sortie » : date, « à venir » (date future ou inconnue) ou « annulé » ; développeur, éditeur, miniature ; zéros estompés ; note colorée (vert à partir de 16, sarcelle 12, ambre 8, rouge dessous) ; ligne « À jouer bientôt » mise en valeur ; la barre du haut (jeux, versions jouées, ou « n jeux sur N » avec filtres) reste cohérente après chaque ajout, modification et retrait.
- **K21 Erreurs et concurrence** [important] : double clic sur l'ajout d'un jeu ou d'une version : un seul ajout, pas de 500 ; IGDB indisponible : message clair dans la recherche, les modales et « Personnaliser », le tableau reste utilisable ; une mutation en échec rétablit la ligne et affiche « Impossible de … : raison. » avec « Réessayer » pour une panne passagère ; deux onglets modifiant la même ligne : pas de corruption ; ligne retirée dans un autre onglet : « ce jeu n'est plus dans le backlog » et elle disparaît.
- **K22 Clavier, focus et thèmes** [confort] : ↓ ouvre le menu des actions, flèches, Début, Fin, une lettre, Échap et Tab le parcourent ; une entrée grisée reste atteignable pour lire sa raison ; modales : focus piégé, Échap comme « Annuler », focus rendu à l'élément d'origine, page dessous figée ; bulles et panneaux fermés par Échap ou un clic à côté ; thème clair et sombre conservé ; « Mon profil » et « Retour à la Citadel ».

- **Z1 Vie complète d'un compte** [critique] : vitrine → « Y accéder » du Backlog → connexion → inscription → activer TOTP → déconnexion → connexion avec TOTP → créer des données GDC et Backlog → changer d'email et de mot de passe → export → vider GDC → supprimer le compte.
- **Z2 Deux utilisateurs en parallèle** [critique] : A et B (deux contextes de navigateur) créent des données et une série manuelle chacun ; aucun ne voit les données de l'autre à aucun moment, ni dans les listes, ni par URL directe, ni après rechargement, ni après déconnexion de l'un.
- **Z3 Compte perdu et retrouvé** [important] : mot de passe oublié avec un TOTP perdu → code de secours → nouveau mot de passe → les anciennes sessions sont mortes, les données intactes.
